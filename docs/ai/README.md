# AI 项目日志

这里是 A 股研究工作台的 AI 可读项目知识库。它用于跨设备、跨会话交接，避免每次重新扫描整个仓库，也让重要变更、验证结果和待办风险可追溯。

## 推荐阅读顺序

1. 仓库根目录 `AGENTS.md`：协作约束、安全边界和验证要求。
2. `project-overview.md`：技术栈、目录、关键模块和稳定约定。
3. `system-status.md`：当前能力、已知限制和下一步优先级。
4. `worklog.md`：按日期记录的重要变更及验证结果，优先读最新条目。
5. `handoff-template.md`：任务未完成或需要交接时使用的模板。

## 文件职责

- `project-overview.md`：低频更新。只保存相对稳定的架构与数据约定。
- `system-status.md`：随项目演进更新。描述现在能做什么、哪里仍有风险。
- `worklog.md`：持续追加。记录重要改动、行为影响和实际验证。
- `handoff-template.md`：交接模板，不记录具体任务内容。

## 维护原则

- 写事实，不写聊天摘要；避免重复源代码已经清楚表达的细节。
- 每次重要功能、修复或架构调整后同步状态与工作日志。
- 代码、测试、数据库 schema 是最终事实来源，文档过期时及时修正。
- 不复制外部文档全文，只记录本项目采用的约定和必要链接。
- 不记录 Token、Cookie、券商凭据、个人持仓或其他敏感数据。
- 已被新结论替代的状态应直接更新；历史变更保留在 `worklog.md`。
